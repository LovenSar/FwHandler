# FwHandler

FwHandler extracts the main data area from raw NAND firmware dumps. It can
remove OOB data, remove interleaved ECC records in the legacy mode, and skip
factory-marked bad blocks. It does not claim to correct bit errors unless an
ECC algorithm and controller-specific ECC byte layout are provided.

## MT29F8G08ABABA profile

The `mt29f8g08ababa` profile describes the Micron 8Gb SLC x8 NAND layout:

- Physical page: `4096` bytes main data + `224` bytes OOB = `4320` bytes.
- Block: `128` physical pages.
- Device organization: `2` planes x `1024` blocks per plane.
- Factory bad-block marker: OOB byte `0` on the first page of a block is
  `00h` for a bad block.
- Minimum ECC requirement: `4-bit ECC per 540 bytes`.

The ECC requirement is a correction-strength requirement. It is not an ECC
byte count, and the data sheet does not define the OOB byte layout generated by
every external NAND controller or programmer. Therefore profile mode removes
the complete 224-byte OOB area instead of guessing ECC offsets.

The data sheet used for this profile is available at:

<https://doc.platan.ru/pdf/datasheets/micron/MT29F8G08ABABA_MICRON.pdf>

## Usage

```text
-h, --help                  Print help
-f, --file FILE             Raw NAND dump
-o, --output FILE           Output file; defaults to FILE.fwhd.bin
--profile NAME              Use a known physical NAND profile
-e, --ecclen N              Legacy interleaved ECC bytes per record
-s, --spare N               Legacy OOB/spare bytes per record
-u, --unit N                Main data bytes per page/legacy record
-p, --page N                Pages/records per block
-b, --block N               Blocks per plane
-P, --plane N               Planes in the device
--tmp                       Keep retained physical records in FILE.fwtmp
--noskipbad                 Retain data from blocks marked bad
--keep-bad-blocks           Alias for --noskipbad
```

For a raw dump whose pages are stored as `4096 + 224` bytes, run:

```powershell
python .\Fwhandler.py --profile mt29f8g08ababa -f .\dump.bin
```

The default output contains only 4096-byte main-data pages. Bad blocks are
skipped as complete 128-page blocks. To retain data from marked bad blocks for
forensic comparison, use:

```powershell
python .\Fwhandler.py --profile mt29f8g08ababa -f .\dump.bin --noskipbad
```

The profile path requires a raw dump with a 4320-byte page stride and a whole
number of 128-page blocks. It does not auto-detect a controller-reordered OOB
layout.

## Legacy mode

Existing generic examples remain supported. With `--spare`, the legacy path
reads `unit + spare` bytes per record and writes only the `unit` main-data
bytes. Without `--spare`, it reads interleaved `unit + ecclen` records and
writes the `unit` data bytes.

```powershell
python .\Fwhandler.py -f .\TC58BVG0S3HTA00@TSOP48_1338.BIN -e 16 -u 512
python .\Fwhandler.py -f .\W29N01HV@TSOP48_3530.BIN -e 8 -s 64 -u 2048 --noskipbad
python .\Fwhandler.py -f .\S34ML01G200TFI00@TSOP48_5332.BIN -e 8 -s 64 -u 2048 -p 64 -b 1024 -P 1 --tmp
```

When `--page`, `--block`, and `--plane` are all supplied in legacy mode, the
input record count must match their product. These options are no longer
overwritten by page-size calculation.

## ECC boundary

Removing OOB/ECC bytes is not the same as repairing ECC bit errors. Actual ECC
correction requires the programmer or controller's ECC algorithm, ECC step
size, and ECC byte offsets. FwHandler currently refuses to infer those values
from the generic `4-bit ECC` requirement.

## Development and tests

The code targets Python 3.8 or newer and uses only the standard library.

Run the regression tests from the workspace root:

```powershell
python -m unittest discover -s .\FwHandler\tests -p "test_*.py" -v
```

The tests cover page extraction, OOB removal, first-page-only bad-block
checking, whole-block skipping, invalid input lengths, CLI geometry parsing,
and the full-device geometry calculation. No full-size NAND image is created
by the tests.
